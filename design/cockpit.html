The problem

Long-running work doesn't fit in a tool call.

A dev server blocks the turn. Backgrounded with & it disappears. Either way the agent ends up re-reading whole logs, in tokens, to find out what happened.

Without Cockpit

  • —The turn blocks until the server is killed
  • —Backgrounded processes vanish with the session
  • —"Is it up yet?" answered by sleeping and guessing
  • —A crash at 3am is noticed by nobody
  • —Whole logs re-read every turn, in tokens

With Cockpit

  • ✓Returns when the port actually answers
  • ✓Shells outlive the turn, the session and the window
  • ✓Waits on a pattern, a port, silence or exit
  • ✓A process that dies is reported as a failure
  • ✓Reads forward with a cursor, greps before it costs

The platform

Cockpit is the part every capability shares.

Bays don't re-solve process ownership, configuration or interface plumbing. They plug into one airframe and inherit all of it.

A daemon that outlives the session

OpenCode's interface and server run in separate threads that can't share memory, and neither survives a restart. cockpitd owns the state instead — shared by every window, self-upgrading, cleaning up after crashes, exiting when idle.

One config for both halves

Agent plugins are configured in opencode.json, interface plugins in tui.json. Cockpit reads one file — global, then project, then plugin entry — and ignores a broken one instead of failing.

A place in the interface

A docked panel, a full console, a sidebar section and a keymap namespace. A bay asks for the slot it needs and inherits the chrome, the theme and the keybind conventions.

A typed wire between them

JSON-RPC over a private socket, with schemas shared by client and daemon and versioned at protocol 1.3. A bay adds methods and events without the others knowing.

Capability bays

Install the suite, or just the instrument you want.

Every bay is its own npm package and can be switched off in config. They share the daemon, so fitting a second one costs nothing.

Install

Two minutes, then ask it to start something.

Everything

$opencode plugin opencode-cockpit --global

All bays, with a switch for each: { "features": { "shell": true } }. New bays arrive with an update and stay off until you turn them on.

One bay

$opencode plugin @opencode-cockpit/shell --global

Same daemon, same config file, same interface slots. Add the rest later without changing anything you already set up.

Stop babysitting your terminal.

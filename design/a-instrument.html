Three things bash in a tool call cannot do

01 · READINESS

Waits on the real signal

Block until the port answers or the log line appears — not a sleep, not a guess. The call returns the moment the thing is actually up.

02 · HEALTH

Reports only what changed

A watcher turns a never-ending log into transitions: ok → fail with the offending line, and silence while it repeats itself. A process that dies is reported as a failure.

03 · CONTINUITY

Survives the conversation

Shells live in a daemon, so they outlast the turn, the session and the window — and a second OpenCode sees the same ones.

Configured once, in one file

OpenCode keeps agent and interface plugins in separate configs. Cockpit reads one file for both, then the project, then the plugin entry.

~/.config/opencode-cockpit/config.json
{
  "kinds": { "e2e": "playwright|cypress" },
  "watch": {
    "presets": {
      "e2e": { "done": "\d+ (passed|failed)",
               "fail": "\d+ failed" }
    }
  },
  "defaults": { "logFile": true, "timeoutSeconds": 900 },
  "ui": { "dockHeight": 16, "defaultView": "log" }
}
Your stack, your categoriesA regex names a kind; the badge and the shell_list filter follow.
Your tools, your rulesA preset defined here travels to the daemon as an explicit rule — no daemon update needed.
Your context budgetguidance and listRunningShells trade tokens per request against how well the model uses shells.
Never fatalAn invalid config is ignored, not thrown. A typo doesn't take your shells down.

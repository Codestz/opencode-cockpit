Background terminals for OpenCode. The agent starts a dev server, waits for the port, and carries on — and tells you when something breaks, instead of re-reading logs for tokens.

Tells you when it breaks

A watcher turns an endless log into transitions: one message on the way down, one on the way back, nothing while the result repeats. A process that dies counts as a failure.

Says who ended it

No more "killed by SIGTERM" with no explanation: a stopped shell reports its time limit, its idle limit, the agent, you, or a crash with its exit code.

The part your agent could never do before

Before

A dev server in a tool call blocks the turn. Backgrounded with &, it is invisible — nobody sees the crash, and the only way to check on it is to read the whole log again, every time, in tokens.

With cockpit

One daemon owns every process. Shells outlive the turn, the session and the window. The agent reads forward with a cursor; you watch the same shells in a docked panel, on the keyboard, in your own terminal.

Install it in one line

$opencode plugin opencode-cockpit --global

Restart OpenCode and ask it to start something. Configuration is optional and lives in one file for both halves of the plugin: ~/.config/opencode-cockpit/config.json.

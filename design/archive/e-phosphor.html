Cockpit is the airframe: a daemon that owns long-lived state across OpenCode's two threads, one config file for both halves of a plugin, a place in the interface for capabilities to render, and a typed protocol between them.

Capabilities bolt into it as bays. Shell is fitted today — background terminals, running on the right.

The airframe

SHARED BY EVERY BAY
01

A daemon that outlives you

OpenCode runs its interface and its server in separate threads, so a plugin's two halves cannot share memory — and neither can survive a restart. cockpitd owns the state instead: it starts on demand, is shared by every window, upgrades itself when newer plugin code connects, reaps what a crash left behind, and exits when idle.

02

One config for both halves

Agent plugins live in opencode.json, interface plugins in tui.json. Cockpit reads one file — global, then per project, then the plugin entry — so a setting is written once and a broken file is ignored rather than fatal.

03

A place to render

A docked panel under the conversation, a full-screen console, a sidebar section and a keymap namespace. A capability asks for the slot it needs; the chrome, the theme and the keybind conventions are the same in every bay.

04

A typed wire between them

JSON-RPC over a private socket, schemas shared by client and daemon, versioned (protocol 1.3). A bay adds methods and events without the other bays knowing, and a version mismatch is reported instead of guessed at.

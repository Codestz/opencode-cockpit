03Reference
Agent tools

What the agent is given

shell_start
Starts and waits properly. Blocks on a port, a pattern, silence or exit — then returns with the opening output.
shell_read
Reads forward. A cursor returns only what is new; grep narrows it before it costs tokens.
shell_watch
Reports transitions. ok → fail with the offending line, nothing while the result repeats, a failure when the process dies.
shell_send
Types into it. Text or keys, for REPLs, prompts and anything interactive.
shell_list
Finds the right one. Filters by kind, status, session or text — including the kinds you defined yourself.
shell_stop / restart
Ends it clearly. The summary says who stopped it and why: a time limit, an idle limit, the agent, or a crash.

Against bash

Why not just run bash in a tool call

Same task, both ways
The taskbash in a tool calla background shell
Start a dev serverBlocks until it is killed, or is backgrounded and lostReturns when the port answers, keeps running
Watch a type checkerRe-read the whole log, every turn, for tokensOne message when it breaks, one when it is fixed
A REPLOne-shot; state is gone by the next callStays open, takes input later
A crash at 3amNobody notices until the next command failsReported as a failure when it dies
05Procedure
Installation

Two minutes, two files

Step 1 opencode plugin opencode-cockpit --global

Step 2 — Restart OpenCode. The daemon starts on first use and stops when idle; shells survive both.

Step 3 — Optional: put your own kinds, watch presets and defaults in ~/.config/opencode-cockpit/config.json. A project may override any of it in .cockpit.json.
